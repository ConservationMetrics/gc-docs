# What's-new post conventions

Facts verified against the repository on 2026-11-18. Re-check them when the newest post or site configuration changes.

## Site wiring

- The posts are a Docusaurus blog, not docs: `docusaurus.config.ts` sets `blog.path: "whats-new"` and `blog.routeBasePath: "/whats-new"`.
- Docs are served from the site root (`docs.routeBasePath: "/"`), so a docs file at `docs/reference/gc-toolkit/gc-explorer/index.md` is `/reference/gc-toolkit/gc-explorer/`.
- `onBrokenLinks` is `throw`: a dead internal link fails `pnpm build`.
- Locales are `en` and `pt`; every build renders both. Images must be locale-safe.
- CI runs `pnpm build` (`deploy.yml`).
- Translations are generated by CI. Never add or edit files under `i18n/` by hand.

## Post anatomy

Taken from `whats-new/2026-11-10.md`, the current reference post.

- **Filename**: publication date, `YYYY-MM-DD.md`. The covered month is not the filename month: "October updates" was published as `2026-11-10.md`.
- **Title**: `<Month> updates`, matching the month covered by the call.
- **Front matter**: only `title` and `date`. No H1 in the body. No tags, authors, slug, description, or `draft`.
- **Intro**: one or two sentences naming the month's theme, then `<!-- truncate -->`.
- **Sections**: `##` per product, no numbering, no bold.
- **Bullets**: `- **Lead-in**: sentence.` One to two sentences. Nested bullets for bug fixes and grouped docs items.
- **Images**: after the bullet, indented two spaces, with blank lines around the block.
- **No closing paragraph** in the recent post; end with the last bullet.

Template:

```md
---
title: October updates
date: 2026-11-10
---

Month theme in one or two sentences.

<!-- truncate -->

## GC Landing Page

- **Short feature name**: What changed and why it matters. See [Doc title](/reference/gc-toolkit/gc-landing-page/).
```

Image block:

```md
- **Dataset cards improvements**: The whole card is now hoverable and clickable.

  ![GC Explorer dataset cards](/img/whatsnew/gc-explorer-dataset-cards.png)
```

The two-space indent keeps the image inside the list item. Without the blank lines, Prettier and MDX can reflow it into the wrong block.

## Section order

Use this order, skipping products with no user-visible change:

1. GC Landing Page
2. GC Explorer
3. GC Scripts Hub
4. GC HTTP Server
5. GC Wildlife Viewer
6. GC Docs

The agenda sets the content; this list only resolves ties and missing order.

## Links

Rules:

- Internal links are root-relative: `/reference/...`, `/guides/...`, `/overview/...`.
- Never use an absolute self-link to the docs site. It breaks locale switching and is forbidden in these posts.
- Directory index pages end with `/`; file pages do not. Match the route the site exposes.
- External links stay absolute: GitHub READMEs, `https://ebird.org/`, blog posts on `conservationmetrics.com`.
- Do not link a docs page that documents an older version when the post describes the new one.

Route to file mapping:

| Route | File |
| ----- | ---- |
| `/reference/gc-toolkit/gc-explorer/` | `docs/reference/gc-toolkit/gc-explorer/index.md` |
| `/reference/gc-toolkit/gc-scripts-hub/dataset-importer` | `docs/reference/gc-toolkit/gc-scripts-hub/dataset-importer.md` |
| `/reference/gc-toolkit/superset/charts/deckgl-scatterplot` | `docs/reference/gc-toolkit/superset/charts/deckgl-scatterplot.md` |
| `/overview/faq/` | `docs/overview/faq/index.md` |

Verification: for a route, test `docs/<route>.md` and `docs/<route>/index.md`; at least one must exist. If neither exists, omit the link or point to the external connector README.

## Images

- Markdown path: `/img/whatsnew/<name>.png`. Never `static/img/...` and never a relative `./` path.
- Files live in `static/img/whatsnew/` (note: no hyphen, unlike the post directory).
- Filenames: `gc-<area>-<feature>.png`, kebab-case, for example `gc-explorer-row-limit-toast.png`.
- Alt text describes the content ("GC Explorer partial results toast"), not the filename ("row-limit-toast").
- Confirm a file exists before referencing it. A missing image fails the build.
- One image per feature is enough. Do not use raw HTML `<img>` tags or externally hosted screenshots.

## Docs-section pattern

```md
## GC Docs

- **New FAQ items**: Added answers on [topic](/overview/faq/) and [topic](/overview/faq/).
- **Updated documentation**:
  - Improved [page title](/reference/...) documentation.
- **Added new documentation**:
  - [Page title](/guides/...).
```

Only include docs work that shipped since the previous post. Do not list routine typo fixes.

## Anti-patterns

Do not copy these from older posts.

| Pattern | Seen in | Do instead |
| ------- | ------- | ---------- |
| `## **GC Landing Page**` | `2026-09-01.md` | `## GC Landing Page` |
| `*` bullets and `-----` rules | `2026-09-01.md` | `-` bullets, no horizontal rule |
| Numbered `###`/`####` headings | `2026-06-01.md` | `##` per product, bold lead-in bullets |
| `[cite: 1, 2, 3]` markers | `2026-07-28.md` | Remove all citation artifacts |
| `<img ... src="https://github.com/user-attachments/...">` | `2026-07-28.md` | `/img/whatsnew/...` Markdown image |
| Absolute self-links to the docs site | `2026-10-21.md` | Root-relative paths |
| `#` H1 in the body | — | Title comes from front matter |
| Tags, authors, slug front matter | — | Only `title` and `date` |

## Validation commands

```bash
pnpm exec prettier --write whats-new/<file>.md
pnpm exec prettier --check whats-new/<file>.md

grep -n "docs\.guardianconnector\.net" whats-new/<file>.md

grep -o "/img/whatsnew/[^)]*" whats-new/<file>.md | sort -u | while read -r p; do
  test -f "static$p" || echo "MISSING: $p"
done

pnpm build
```

Expected: the absolute-link grep and the image check print nothing, and the build succeeds for `en` and `pt`.

## Known repository issue

The translation workflow (`.github/workflows/translate.yml`) watches `whatsnew/**`, but posts live in `whats-new/**`, so posts are currently not auto-translated. Do not work around it by editing `i18n/`; report it as a separate fix.
