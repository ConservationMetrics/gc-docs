# Guardian Connector documentation (gc-docs)

Docusaurus site for docs.guardianconnector.net. Content is Markdown, and the build is the main check.

## Commands

- Install: `pnpm install`
- Dev server: `pnpm start`
- Build (must pass before committing): `pnpm build`
- Format one file: `pnpm exec prettier --write <file>`

CI builds with `pnpm build` and deploys from `main`.

## Content rules

- Docs live in `docs/`; the Docusaurus docs plugin serves them from the site root.
- Monthly product updates live in `whats-new/`; the blog plugin serves them at `/whats-new/`.
- All images go in `static/img/` and are referenced with absolute paths such as `/img/guides/example.png`. Never use relative image paths: the site builds every locale, and relative paths break translated pages.
- Internal links are root-relative: `/reference/gc-toolkit/gc-explorer/`, `/guides/...`, `/overview/faq/`. Never link to the docs site by absolute URL; absolute self-links break locale switching.
- `onBrokenLinks` is `throw`, so a dead internal link fails `pnpm build`. Verify a target file exists under `docs/` before linking it.
- Do not edit `i18n/` by hand. Translations are generated by CI.
- Read `CONTRIBUTING.md` before changing structure, navigation, or images.

## Monthly what's-new posts

When asked for the monthly product update ("what's new", "monthly updates", product update post), load `.agents/skills/whats-new/SKILL.md` and follow it. It covers extracting changes from the call agenda and transcript, editorial triage, screenshot planning, link and image rules, and validation.

## Scope

- Change only the files the task needs; do not reformat or reorder unrelated content.
- Do not commit or push unless explicitly asked.
